# 08 · 部署与运行

> Makefile 是全部 60+ 命令的唯一入口（`make help` 查看全部）。三种运行形态：**Docker 开发**、**本地裸机**、**生产部署**。

## 1. 环境准备

```bash
cp .env.example .env     # 编辑填入 POSTGRES_PASSWORD / SECRET_KEY / MINIO_SECRET_KEY 等
```

`.env` 关键配置分组：数据库（POSTGRES_*）、缓存（REDIS_*）、MQTT（MQTT_* 含 Dashboard 密码）、对象存储（MINIO_*）、应用（SECRET_KEY / APP_ENV / CORS_ORIGINS）、Agent（AGENT_* 默认关）、助手（ASSISTANT_*）、通知（WECOM_WEBHOOK 可空=禁用外发）。

Windows 开发机注意：控制台默认 GBK，跑契约脚本前建议 `$env:PYTHONIOENCODING='utf-8'`（两个契约脚本已自带 UTF-8 重配置，不依赖该变量）。

## 2. 开发环境（Docker Compose，推荐）

```bash
# 1) 一键启动全部依赖（postgres/redis/emqx/minio/go2rtc/backend/ai-service/frontend）
make up                        # = docker compose up -d

# 2) 初始化数据库（建表 + 空间索引 + 种子数据）+ Alembic 打桩
make db-init
make migrate-stamp             # ★ 新环境必做，见 §5 双轨制

# 3) 启动后端 / 前端（热重载；也可直接用 compose 里的 backend/frontend 容器）
make dev-backend               # uvicorn :8000 --reload
make dev-frontend              # vite :5173

# 4) 演示与验证
make simulate                  # 边缘盒模拟器：真实节奏（抽帧 8fps，上报冷却 90s）
make demo                      # 演示节奏（冷却 3s，几秒看到连续告警）
make smoke                     # 端到端冒烟：事件→派单→状态流转
```

打开 <http://localhost:5173> 查看大屏。EMQX Dashboard 在 :18083，MinIO 控制台 :9001，go2rtc :1984。

### 常用运维目标

| 命令 | 作用 |
| --- | --- |
| `make ps / logs / down / restart` | 容器状态 / 日志 / 停止 / 重启 |
| `make ensure-partitions` | 开发环境补建 t_track 当日及未来分区（幂等；缺分区机器人遥测写不进去） |
| `make db-reset` | **危险**：删数据卷重建 |
| `make bootstrap-demo-users` | 写入登录页四个演示账号（admin/operator/approver/viewer） |
| `make knowledge-demo-seed` | 显式写入知识智能体演示数据（可重复执行） |

### 演示审批模式（P0 演示高光）

开关唯一真源是本地 `.env` 的 `AGENT_REQUIRE_APPROVAL_FOR_WRITE`：

```bash
make demo-approval-up          # 打开审批开关并重建（拍「人机协同」镜头）
make demo-approval-check       # 打印后端实际生效的审批策略
make check-demo-accounts       # 真实登录探测四个演示账号（只读）
make demo-approval-down        # 恢复默认策略
```

## 3. 本地裸机模式（无 Docker）

参考 `docs/deployment.md`「本地裸机模式」，用托管 venv 跑后端。**注意此时 `/health` 会如实返回 `degraded`/`down`——这是设计行为，不是 bug**（健康降级语义由 `test_health_degradation.py` 守卫）。

## 4. 生产部署（docker-compose.prod.yml）

与开发 compose 的核心区别：
- 前端只绑定宿主机 `127.0.0.1:8080`；PostgreSQL/Redis/MinIO/后端/AI 服务**不暴露公网**
- EMQX 默认只绑回环；真实设备接入时把 `MQTT_BIND_ADDR` 改到受防火墙/VPN 保护的网卡
- 首启只执行 `01_schema.sql`，**不导入演示种子**
- `validate_production_settings()` 在 APP_ENV=production 时强制 fail-closed（占位密码直接拒绝启动）

```bash
# 1) 生产环境变量（替换全部 CHANGE_ME）
cp .env.production.example .env.production

# 2) 校验配置 + 生成 EMQX 首启密码哈希
make prod-config
make prod-mqtt-bootstrap

# 3) 构建并启动
make prod-up

# 4) 新库 Alembic 对齐（01_schema.sql → 当前 head）
make prod-migrate-stamp

# 5) 创建正式管理员（交互式输入至少 12 位密码）
make prod-create-admin

# 6) 滚动创建 t_track 未来 14 天分区（服务器上唯一可用的分区入口）
make prod-track-partitions

# 7) 生产演示账号（含生产闸门 --confirm-production）
make prod-bootstrap-demo-users
```

随后把 `deploy/nginx/seasight.conf` 安装到宿主机 Nginx（替换 `server_name`、TLS 证书、真实域名）。**对公网只开放 80/443，不要放通 8000/1984/9000/18083**。

### 无 git remote 的同步方式

仓库未配置远程，走打包上传：`make deploy-package`（生成 `artifacts/deploy/*.tar.gz` + SHA256 清单）→ 上传 → `make deploy-verify`（只读核对线上构建，需设 `SEASIGHT_PRODUCTION_URL`）。

## 5. 数据库迁移双轨制（改表前必读）

| 轨道 | 负责 | 工具 |
| --- | --- | --- |
| **A：初始建表** | PostGIS 扩展、分区表、触发器 | `backend/db/init/01_schema.sql`（容器首启自动执行） |
| **B：增量变更** | 之后所有改表 | Alembic（唯一主配置 `backend/alembic.ini`） |

两轨靠空迁移 `20260918_1000_baseline` 对齐，当前 head：`20260919_1900_knowledge_assets`。

```bash
make migrate-stamp                        # 新环境首次：标记 baseline 已应用（不执行 SQL）
make migration m="给 t_event 加 severity 字段"   # autogenerate（生成后必须人工检查！）
make migrate                              # 应用
make migrate-history                      # 查看历史
make migrate-sql                          # 导出 SQL 供 DBA 审核（离线）
```

**两条铁律**：
1. 新环境不先 `make migrate-stamp`，第一次 autogenerate 会把已存在的表当缺表，生成一堆 create_table 一执行就报错。
2. `alembic.ini` **必须纯 ASCII**——Alembic 读 ini 用 `encoding="locale"`，中文 Windows 按 cp936(GBK) 解码，任何中文注释都会让所有迁移命令崩溃。

## 6. 边缘程序与识别链路

```bash
make test-cv-selftest   # 合成海面自检：检测→时序→报文 全链路（200 帧，无需摄像头）
make run-edge-demo      # 合成海面 + --show 弹窗看检测框
make run-edge           # 真实 RTSP 取流（改 edge/config.yaml 的 source）
make vision-compare-export  # 导出双通道对照页数据（需 torch/ultralytics）
```

## 8. 验证矩阵（何时跑什么）

| 场景 | 命令 |
| --- | --- |
| 提交前 | `make check`（秒级静态）+ `make test`（92s 全量） |
| 改了 MQTT / 契约 / 枚举 | `make check-contract` + `make check-contract-selftest` |
| 改了派单 / 消费者 | `make check-dispatch-selftest` + `check-finalize-selftest` + `check-pel-selftest` |
| 改了边缘检测 / 时序 | `make test-edge` + `make test-cv-selftest` |
| 集成验收 | `make up && make smoke`，然后 `make test-browser` / `make fault-acceptance` / `agent_real_state_acceptance.py` |
| 公开仓库前 | `make check-public-repo-privacy`（必须退出码 0） |
| 演示前 30 秒 | `make demo-approval-check` + `make check-demo-accounts` |
