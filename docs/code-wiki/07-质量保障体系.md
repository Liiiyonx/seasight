# 07 · 质量保障体系

> 这个项目最独特的资产不是某个功能，而是**七层验证体系**和「守卫自身也要被验证」的自证机制。每一层针对一类特定的静默失效缺陷。

## 1. 七层验证总览

| 命令 | 守住什么 | 典型能抓到的错 |
| --- | --- | --- |
| `make test-edge` | 算法逻辑 + 参数真源 + 检测器行为 + 双通道隔离 | 抑制率越界、文档写 5 代码写 6、暗色渔具被当阴影剔掉、world 被套 cv 门限后全灭、cv 实现被 world 改动污染 |
| `make test` | 仓库全量 1061 项：契约 + 推理后处理 + 派单 + 认证权限 + edge/ml | 状态机非法迁移、上报响应谎报派单成功、`/health` 撒谎、前端伪造角色提权、写接口漏挂 require_operator |
| `make check-api` | 前后端接口一致性 | 前端调了后端不存在的路径（只在点某个页签才 404） |
| `make check-gitignore` | 仓库卫生 | 运行时状态/模型权重/密钥被误提交 |
| `make check-contract` | MQTT/枚举契约漂移 | 订阅了却路由不到、状态映射漏项、类别枚举五处不一致 |
| `make check-data` | 训练数据完整性 | 图片缺标签（训练静默少样本）、类别索引越界 |
| `make test-cv-selftest` | 真实识别链路 | 检测器和时序校验器没接上、报文契约漂移、合成海面检不出目标 |

另有 `make check-public-repo-privacy`（开源前隐私扫描：本机路径/生产地址/验收证据，公开前必须退出码 0）。

## 2. 自证机制（防止守卫自己静默失效）

> 核心信条：**一个永远返回「全绿」的检查脚本比没有脚本更糟——它给的是虚假的安全感。**

| 命令 | 注入缺陷数 | 验证对象 |
| --- | --- | --- |
| `make check-contract-selftest` | 12 种 | 契约漂移脚本 + WS 契约测试（含字节级注入-还原 SHA256 自证） |
| `make check-events-selftest` | 4 种 | 事件上报契约测试（含「tuple 未解包」全工程扫描器） |
| `make check-dispatch-selftest` | 5 种 | 派单引擎测试（结构断言：形参被使用、权重必须不同） |
| `make check-finalize-selftest` | 7 种 | 派单收尾 AST 守卫（凡调 dispatch_for_event 必调 finalize_dispatch） |
| `make check-pel-selftest` | 4 种 | Redis PEL 回收测试 |
| `make check-evidence-scripts-selftest` | — | 华为 ICT 证据脚本未配置时不伪造成功 |

## 4. 历史缺陷形态学（为什么每一层守卫存在）

README 里详尽记录了六种「测试全绿但功能坏掉」的缺陷形状，这是理解本仓库测试设计的钥匙：

| 形状 | 实例 | 破法 |
| --- | --- | --- |
| **文档声明 N 项、代码实现 N-1** | MQTT `cmd/ack` 路由判据永不成立、状态映射漏 `done` | `check_contract_drift.py` 穷举比对两个集合 |
| **手工拼装负载缺字段** | `task_update` 4 字段只拼 3 个，前端静默 undefined | 契约提常量 + AST 扫描所有推送点 |
| **把"本次调用产物"当"可事后反查"** | 派单后查全库最新一条任务充数 → 恒报派单成功、并发时 task_id 指向别人的任务 | `_try_dispatch` 签名改 `-> Task \| None`，出口显式 return 用 AST 钉死 |
| **没有断言的优化 = 不存在** | 类别加权收了 task 形参却没用，排序实际只剩距离一维 | 结构断言（形参被使用 + 权重必须不同） |
| **实现了 N 步只接上 N-2** | 定时补派/补派 API 只建任务不下发 MQTT，任务永远 assigned 且无任何日志 | 收敛到 `finalize_dispatch` 唯一出口 + AST 断言接线 |
| **不 ACK 就必须有人认领** | `xreadgroup(">")` 不读 PEL，消息永久滞留 + 内存泄漏 | `xautoclaim` 认领挂起条目 + PEL 测试 |

静态守卫不只查业务代码，也查**守卫自身**：`test_static_guards.py` 全工程扫描「收而不用」形参；`check-contract-selftest` 曾连续四次发现检查工具自身失效（AST 漏 async 函数、判据写错、误读文档、注入锚点失效）。

## 5. 测试运行速查

```bash
make test           # 全量 pytest（1061 项，~92s，无需基础设施）
make test-edge      # 边缘 86 项（时序 11 + cv 16 + world 59）
make test-cv-selftest  # 合成海面全链路自检（检测→时序→报文）
make check          # check-api + check-gitignore + check-contract（静态，秒级）
make smoke          # 端到端冒烟（需 make up）
make test-browser   # E1 浏览器验收（node scripts/browser_acceptance.mjs）
# 全部自证: check-contract-selftest / check-events-selftest /
#          check-dispatch-selftest / check-finalize-selftest / check-pel-selftest
```

验收报告落盘 `artifacts/{browser-acceptance,fault-acceptance,agent-real-state-acceptance,nexent-acceptance}/latest.json`。

## 6. 协作规范

- 分支：每人独立分支，主分支只由负责人合并
- 提交前缀：`feat:` / `fix:` / `docs:` / `refactor:`
- 文档：Markdown 存 `docs/`，重要决策写 `docs/decisions.md`（ADR）
- 敏感信息：只放本地 `.env`，永不提交（`check_gitignore.py` 守卫）
