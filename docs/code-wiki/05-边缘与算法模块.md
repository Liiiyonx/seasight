# 05 · 边缘与算法模块（edge/ + ml/）

## Part A · 边缘感知软件（edge/）

### A1. 主程序（edge/main.py）

真实边缘程序，主链路：**取流 → 检测 → 时序校验 → MQTT 上报**。

| 函数/类 | 职责 |
| --- | --- |
| `open_source()` / `next_frame()` | 取流入口，支持 4 种源：`synthetic`（合成海面，无摄像头自检）/ `camera`（本机摄像头）/ `rtsp`（真实摄像头）/ 视频文件 |
| `EdgeRuntime.__init__()` | 组装检测器 + `TemporalValidator` + 上报节流（冷却 cooldown、最小间隔 min-interval）+ 缓存与状态 |
| MQTT 连接逻辑 | 连接、主题生成（`Topics` 同款契约）、retained 状态发布（含 LWT 遗嘱） |

CLI 用法（见 Makefile）：
```
make run-edge           # 真实 RTSP（改 edge/config.yaml 的 source）
make run-edge-demo      # 合成海面 + --show 弹窗看检测框
make test-cv-selftest   # --source synthetic --dry-run --max-frames 200 全链路自检
```

自检口径（200 帧合成海面）：原始检测 599 条 → 确认事件 3 个，时序抑制率 76%（该口径是"被时序过滤的检测数/输入检测数"，**不是检测精度**；模拟器三场景为 42%~43%，两者输入集不同不可互替）。

### A2. 配置（edge/config.yaml）

| 段 | 关键项 |
| --- | --- |
| `detector.backend` | `cv`（默认，主告警链路）/ `world`（开放词汇演示对照，默认不启用） |
| 检测器 | KNN 背景建模、阴影检测、白亮泡沫通道、暗色渔具通道、形态学、轮廓面积阈值 |
| `temporal` | 窗口帧数、最小命中数、网格大小、置信度门限、IoU、最大丢失帧数 max_misses |
| 上报 | 冷却、最小间隔、点位信息 |
| MQTT | broker 地址、凭据、site/device ID |

参数真源一致性由测试守卫：`make test-edge` 含「代码默认值 vs 设计文档参数表」一致性用例（曾抓到文档写 5、代码写 6 的 max_misses）。

### A3. 双通道检测器（edge/detector/）

两条实现**同一输出契约**（bbox + 类别 + 伪置信度）的通道，互相隔离：

**CvDetector（detector/detector.py）— 主链路**
- `detect()` 流程：背景减除 ∪ 颜色通道 → 形态学 → 轮廓提取 → ROI 裁剪 → 规则分类 → 置信度排序
- `_foreground_mask()`：KNN 背景建模合并白亮通道（泡沫）与暗色通道（渔具）——设计动机：暗色渔具会被背景建模当阴影剔除、静止泡沫会被学成背景后永不报警，两条通道都有针对性测试
- 定位：零数据依赖、纯 CPU、阈值当场可调；召回不如 YOLO，误报由时序校验压制
- 16 项合成帧测试（`test_detector.py`）：四类目标分类、bbox 越界、静止目标不丢、反光降分、ROI 生效、类别与 AI 服务/数据集 yaml 三处对账、默认值与 config.yaml 对账、cv 通道实现与 world 无关（防污染）

**WorldDetector（world_detector.py）— 对照通道**
- YOLO-World 开放词汇零样本；接口与 CvDetector 对齐，支持现场加词、模型懒加载、**测试注入假 runner**（59 项测试 `test_world_detector.py` 不需要 torch）
- 不复用 cv 的 0.45 门限（各有各的置信度体系）；未映射提示词不允许静默变 other（label_map 穷举映射 + fallback 统计）

**辅助模块**
- `label_map.py`：开放词汇提示词 → 四类契约类别的**穷举映射表**
- `clip_shim.py`：CLIP 文本编码器依赖探测垫片（可选依赖，缺失可降级且可观测）
- `test_metrics.py`：时序链路指标口径测试

### A4. 时序校验（TemporalValidator，edge/simulator/simulator.py 内）

误报抑制核心算法——区分浪花瞬态目标与持续垃圾目标：
- **单帧检测不确认**：需窗口内累计最小命中数
- `_match()` 关联条件：**同类 + 中心位移 + IoU** 同时满足才算同一目标（防随机噪声被串成轨迹）
- 连续 `max_misses` 丢失才移除跟踪（静止/慢速目标不丢）
- 11 项测试（`test_temporal.py`）：单帧不确认、抽帧压噪、抑制率界内、参数文档一致性

### A5. 边缘盒模拟器（edge/simulator/simulator.py）

无真实设备时驱动平台演示：自制检测框（不依赖摄像头与模型）直接按 `Topics` 契约发 MQTT 报文。
- 三场景：`demo`（演示节奏，`make demo` 冷却 3s）/ `stress` / `regression`（`make simulate` 真实节奏冷却 90s）
- 场景汇总输出时序抑制率（42%~43% 口径来源）

## Part B · 模型训练管线（ml/）

### B1. 目录结构

```
ml/
├── configs/
│   ├── seasight.yaml          # 数据集配置（类别、路径、stats 段体检统计）
│   └── train_args.yaml        # 训练超参
├── datasets/manifests/        # 数据清单（真实数据不入库）
│   ├── example_train.yaml / example_val.yaml / example_test_independent.yaml / example_blind_live.yaml
│   └── README.md              # 清单协议说明
├── scripts/
│   ├── train_two_stage.py     # 两阶段训练
│   ├── export_onnx.py         # ONNX 导出（对接 ai-service）
│   ├── check_dataset.py       # 数据集体检（make check-data / --write-stats）
│   ├── convert_annotations.py # 标注格式转换
│   ├── calibrate_camera.py    # 相机标定
│   ├── evaluate_opencv.py     # OpenCV 通道评测
│   └── validate_dataset_integrity.py  # 数据完整性校验
└── tests/                     # 管线自身测试（标定/清单/评测/体检/标注管线/数据协议接线）
```

### B2. 数据协议与检测链路关系

```
原始图片 + 标注
 → check_dataset.py 体检（图片缺标签、类别索引越界 → make check-data 守卫）
 → convert_annotations.py 转换 → 训练清单 manifests/*.yaml
 → train_two_stage.py 训练 → export_onnx.py 导出 ml/models/best.onnx
 → ai-service（Dockerfile.ai, AI_MODEL_PATH=/ml/models/best.onnx）推理
 → 备选通道：数据攒够后无缝替换 cv 主链路（检测器接口一致）
```

- 清单协议区分 train / val / **test_independent**（独立测试集）/ **blind_live**（盲测）——当前独立测试集为空，`artifacts/metrics/opencv_latest.json` 为 `not_evaluated`，口径诚实
- `evaluate_opencv.py` + `scripts/export_channel_compare.py`（根级）产出双通道对照页数据（`make vision-compare-export`，需 torch）

### B3. 与边缘检测器的关系

| 通道 | 数据需求 | 状态 |
| --- | --- | --- |
| cv（OpenCV） | 零数据依赖 | **当前主链路**（`detector.backend: cv`） |
| world（YOLO-World） | 零样本开放词汇 | 演示对照，默认关闭 |
| YOLO11 + ONNX | 需攒数据训练 | 管线就绪（ml/），接口一致可无缝切换 |

**类别契约**四类 foam/plastic/fishing_gear/other 在五处保持一致（前端 constants / cv 检测器 / world label_map / AI 服务 / 数据集 yaml），由 `make check-contract` 穷举对账。
