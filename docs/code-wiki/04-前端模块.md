# 04 · 前端模块（frontend/）

> Vue 3.5 + Vite + Vue Router 4 + Pinia。开发模式 `make dev-frontend`（:5173），生产模式 nginx 托管静态产物（`--profile prod`）。

## 1. 依赖与构建

`package.json` 关键依赖：

| 依赖 | 用途 |
| --- | --- |
| vue 3.5 / vue-router 4.4 / pinia | 框架三件套 |
| axios | HTTP 客户端 |
| echarts | 图表（趋势、类别分布、报表） |
| leaflet | 地图（天地图瓦片，政务合规） |
| three | 机械臂 / 仿真 3D 场景 |
| mpegts.js | HTTP-FLV 低延迟视频播放（flv.js 已停维护的替代） |

[vite.config.js](../../frontend/vite.config.js) 要点：
- `@` 别名指向 `src`
- 开发代理：`/api` → 后端 :8000、`/stream` → go2rtc :1984、WebSocket 代理
- 手动 chunk 拆分：`echarts` / `vendor` 独立分包

## 2. 应用入口与路由

入口 `src/main.js`（挂载 App + router + Pinia）。路由表 [src/router/index.js](../../frontend/src/router/index.js)：

| 路径 | 视图 | 说明 |
| --- | --- | --- |
| `/login` | LoginView | 登录（noLayout） |
| `/dashboard` | DashboardView | 监测大屏（realtime） |
| `/events` | EventsView | 事件中心（realtime） |
| `/tasks` | TasksView | 工单看板（realtime） |
| `/simulation/:taskId` | SimulationView | 工单执行仿真（hideInNav，3D） |
| `/devices` | DevicesView | 设备态势（realtime） |
| `/reports` | ReportsView | 治理报表 |
| `/assistant` | ChatView | 智能助手（拖图检测；`?session=` 直达会话） |
| `/agents` | AgentsView | 智能体控制台（轨迹回放/审批队列/工具目录/评测雷达/经验库；`?run=` 直达） |
| `/knowledge` | KnowledgeView | 知识智能体（资产/本体/检索/证据链） |
| `/vision-compare` | VisionCompareView | 双通道对照（定性，`?sample=` 直达） |
| `/analyze` | redirect → /assistant | 保留函数式 redirect 传递 query（`?sample=` 是链路唯一参数载体） |

**路由守卫**：`beforeEach` 校验 `isLoggedIn()`（`utils/auth.js`），未登录重定向 `/login` 并带 `redirect` query 回跳；`afterEach` 设置页面标题 `· 探海灵眸 Oceanus`。

> 路由上的注释记录了两个历史坑：`/agents` 一度被 redirect 到 /assistant 导致轨迹回放等能力"消失"；`/analyze` 曾用字符串 redirect 丢 query 导致点样本图无反应。均以保留 name + 函数式 redirect 修复。

## 3. API 层（src/api/）

### http.js — Axios 封装

- 请求拦截：注入 `Authorization: Bearer <token>`
- 响应拦截：拆后端统一信封 `{code, data, message, trace_id}`；统一处理 401（清 token 回登录）/ 403 / 404 / 500 / 超时

### index.js — 全量接口映射

| 分组 | 覆盖接口 |
| --- | --- |
| 事件 / 工单 / 仿真 / 设备 / 机器人 / 统计 / 报表 | events, tasks, simulations, devices, robots, stats, reports |
| 认证 | authApi.login / me |
| AI 图片分析 | ai.analyzeImage |
| Agent 运行时 | runtime status、run 发起/取消、steps、tools、approvals、evals |
| 对话助手 | sessions、messages、图片上传 |
| 知识智能体 | 资产、本体、检索、决策轨迹与证据链 |

前后端接口一致性由根级脚本 `scripts/check_api_contract.py` 静态对账（`make check-api`）——专抓"前端调了后端不存在的路径、只在点某个页签时才 404"这类缺陷。

## 4. 状态管理（src/stores/realtime.js）

唯一的 Pinia store，大屏与多页共享的实时状态：统计概览、事件流、设备、机器人、热力图数据、工单动态、遥测。由 WebSocket 推送驱动 feed 更新，提供统一的加载 / 刷新动作。

## 5. 实时推送（src/utils/realtime.js）

- 连接 `/api/v1/ws/alerts`，token 通过 query 传递（WebSocket 无法带 header）
- 心跳保活、断线检测、**指数退避重连**，暴露 `connected` 状态供 store 使用

## 6. 认证与权限（src/utils/auth.js）

- token + 用户角色信息存 `localStorage`，`isLoggedIn()` 供路由守卫
- **权限事实来自服务端 JWT 验签**——前端角色只做展示层裁剪；曾出现的"改 localStorage 即可提权 admin"漏洞根因是后端读 `X-User`/`X-Role` 自填头，已修复并由后端 `test_auth_guard.py` 守卫

## 10. 与后端的契约边界

- REST：统一信封 `{code, data, message, trace_id}`，`code=0` 成功
- WebSocket：`task_update` 推送 4 字段（task_id/event_id/robot_id/status）——前端把它当"有更新就重拉"的触发器
- 视频流：同源相对路径 `/stream/...` 由 Nginx 反代到 go2rtc，避免泄露容器内主机名
- 类别/状态枚举：三处对账（前端 constants / AI 服务 / 数据集 yaml）由 `make check-contract` 守卫
