# 01 · 项目总览

## 1. 项目定位

**探海灵眸 Oceanus** 是一套面向海洋养殖区海漂垃圾治理的**三端协同智能系统**：

```
岸基摄像头发现  →  平台自动派单  →  水面机器人清理  →  数据回传形成治理闭环
   （感知）           （决策）            （执行）             （数据价值）
```

它是**区域级治理系统**，不是单台清洁船。与市面单机竞品（WasteShark / Clearbot 等）的核心差异：

| 维度 | 单机竞品 | 探海灵眸 |
| --- | --- | --- |
| 形态 | 单机产品 | 感知—决策—执行三级系统 |
| 识别对象 | 通用漂浮垃圾 | 中国养殖区特色垃圾（EPS 泡沫浮球碎片、废旧渔具、饵料袋） |
| 分拣 | 无分类收集 | 打捞即三仓粗分 + 岸基精分 |
| 数据价值 | 清理量 | 热力图、派单调度、量化报表、溯源分析 |

**重要边界**：机器人本体可替换、可离线。软件侧已具备事件理解、规划、工具调用、策略守卫、审批、派单、MQTT/WebSocket 收尾、审计、回放和离线评测闭环，可独立作为「海漂垃圾治理决策与调度智能体软件」参赛运行。

## 2. 领域核心概念

| 概念 | 含义 | 代码载体 |
| --- | --- | --- |
| **事件 Event** | 边缘盒识别到的一片垃圾（含类别、位置、时间、证据图） | `t_event` 表，`app/models/event.py` |
| **工单/任务 Task** | 派给某台机器人的清理任务，带状态机 | `t_task` 表，`app/models/task.py` |
| **派单 Dispatch** | 把事件转化为工单的决策过程（五步筛选 + 防抖合并） | `app/services/dispatch.py` |
| **垃圾四分类** | foam（泡沫）/ plastic（塑胶）/ fishing_gear（渔具）/ other | `WasteClass`，`app/models/event.py` |
| **设备 Device** | 岸基摄像头 / 无人机 / 水面机器人三种类型 | `t_device` 表，`app/models/device.py` |
| **时序校验** | 边缘侧误报抑制：单帧检测不确认，需连续命中才上报 | `TemporalValidator`，`edge/simulator/simulator.py` |
| **ACK 回执** | 机器人收到指令后的确认，超时换车重派 | `t_task_ack` 表 + `app/mqtt/ack.py` |
| **Agent Run** | 智能体一次决策运行的完整轨迹（步骤、审批、记忆） | `t_agent_run` 等 5 表，`app/models/agent.py` |
| **知识资产** | 文档/表格/图片/事件/遥测等登记入库的多模态资产，版本不可变 | `t_knowledge_asset` 等 8 表，`app/models/knowledge.py` |

## 3. 五个软件子系统

| 子系统 | 代码位置 | 职责 |
| --- | --- | --- |
| 边缘感知软件 | `edge/`（main.py + detector/ + simulator/） | 岸基摄像头旁边缘盒：取流 → 检测 → 时序校验 → MQTT 上报 |
| 机载软件 | `edge/arm_bridge/` + `edge/device_sim/` | 打捞机器人船载单元（机械臂桥接与设备协议模拟） |
| 数据平台 | `backend/` + `frontend/` | 事件、派单、工单、报表、权限、大屏展示 |
| 模型训练管线 | `ml/` | 数据集体检、两阶段训练、ONNX 导出、标定、评测 |
| AI 推理服务 | `backend/app/services/ai/`（独立容器，端口 8081） | ONNX Runtime 推理 + NMS 后处理，与平台同机部署 |

另有横向能力 **知识智能体**（`backend/app/services/knowledge.py` + `api/v1/knowledge.py`）与 **Nexent MCP 集成**（`integrations/nexent/`），把知识资产、动态本体、多跳检索、决策证据链暴露给外部智能体框架。

## 4. 技术栈

| 层 | 选型 | 关键理由 |
| --- | --- | --- |
| 后端框架 | Python 3.11 + FastAPI 0.115 | 异步、自带 OpenAPI 文档、与算法同语言 |
| ORM / 迁移 | SQLAlchemy 2.0 (asyncio) + Alembic 1.14 | 异步 ORM；迁移走「双轨制」（见 [08-部署与运行](./08-部署与运行.md)） |
| 主数据库 | PostgreSQL 14 + PostGIS | 空间索引（GiST）支撑热力图与就近派单 |
| 缓存/队列 | Redis 7（Streams 消费者组） | 缓存 + 事件/派单队列 + PEL 回收 |
| 消息总线 | EMQX 5 (MQTT, aiomqtt) | 移动网络友好的设备接入，QoS1 幂等去重 |
| 对象存储 | MinIO | 告警帧与作业影像 |
| 流媒体 | go2rtc | 单文件零依赖，RTSP → WebRTC/FLV |
| 前端 | Vue 3.5 + Vite + Vue Router 4 + Pinia | 政务项目生态成熟 |
| 可视化 | ECharts + Leaflet + Three.js | 图表 / 地图 / 机械臂 3D 仿真 |
| 视频播放 | mpegts.js | HTTP-FLV 低延迟播放 |
| 检测（主链路） | OpenCV 4.10 headless | **零数据依赖**、纯 CPU、阈值当场可调 |
| 检测（对照通道） | YOLO-World 开放词汇零样本 | 演示对照用，默认不启用 |
| 检测（备选） | YOLO11 + ONNX Runtime / TensorRT | 数据攒够后无缝替换（接口一致） |
| 认证 | python-jose (JWT) + passlib/bcrypt | 服务端签名令牌，四角色权限 |
| 容器 | Docker Compose | 单机一键起全套 |

## 6. 四类用户角色

权限必须来自服务端签名令牌（JWT），不信任前端填的任何头：

| 角色 | 权限 |
| --- | --- |
| `admin` | 全部 |
| `operator` | 写操作（创建任务 / 更新状态 / 补派），由 `require_operator` 依赖守卫 |
| `approver` | 只读 + Agent 人工审批决定权 |
| `viewer` | 只读 |

四角色由登录签发的签名令牌承载，后端从 `Authorization: Bearer` 验签解析。曾经的实现读前端自填的 `X-User`/`X-Role` 头（改 localStorage 即可提权），已重构修复，守卫见 `backend/tests/test_auth_guard.py`。
